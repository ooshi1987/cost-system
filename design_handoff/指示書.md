# 指示書(Claude Code 向け) — 現場スマホ画面をモックアップ「Lane A」に合わせて実装

対象リポジトリ: 「cost system」(Next.js App Router + TypeScript + Prisma/PostgreSQL + Tailwind、amberアクセント、全データ`storeId`スコープ)

## 背景
現場スタッフがスマホで撮影・入力する5画面を、デザイン `Costra 全体モックアップ.dc.html` の `phone-row`(1〜5)に合わせて実装/リファインする。既存実装があるものは配色・構成のみモックアップに合わせ、未実装のものは新規追加する。まず現状のリポジトリを確認し、各画面がどこまで実装済みか判断してから着手すること(全て作り直す必要はない)。

## 対象画面と仕様

### 画面1: ホーム(`/` or `/home` 等、既存のモバイルホームを踏襲)
- 店舗名ヘッダー+通知アイコン(バッジ)。
- KPIサマリカード: 当月の純額(大きく緑文字)、売上/支出の内訳、構成比バー。既存の `dashboard/stats` API か同等のものを流用。
- 要確認件数バナー(タップで確認画面へ)。
- アクションカード4種: 「納品書・レシートを撮影」(プライマリ、大)/「売上を撮影」/「小口現金」/「経費を手入力」。各カードは対応する撮影・入力フローへの導線。

### 画面2: 納品書 撮影→読取結果
**プロジェクトのCLAUDE.md必須仕様に準拠**(既存の類似実装 `/api/menu-items/import` の仕組みを参考にできる):
1. OCR/AI読取後の明細をその場でインライン編集(品目名・数量・金額)。行削除可。
2. 読取に自信がない項目は要確認フラグ(琥珀 #b06a12 / 背景 #fbe7cf)でハイライトし、画面上部に「要確認 N件」。
3. 明細合計とレシート記載合計(OCR値)を自動突合。一致なら緑バッジ「✓ 一致」、ずれていれば上部バッジ+該当箇所両方に琥珀で「差額 ±¥X」。
4. 編集する度に合計・照合結果を即再計算。
- 保存時は `DeliverySlip` + `DeliveryItem`(既存の命名規約)に書き込む。

### 画面3: 売上 撮影(AIレジ締め)
- 画面2と同じ編集＋照合の必須仕様を適用(内訳: 現金/キャッシュレス/客数など、タップで編集、要確認フラグ、合計照合バッジ)。
- 一致時は「✓ 一致」(緑)、不一致は差額表示(琥珀)。保存で `Transaction`(収入)として記録。

### 画面4: 小口現金
- 「帳簿上の残高」(自動計算値、既存の入出金から算出)を表示。
- ユーザーが「実際の残高」を入力(テンキー)。
- 差額を自動計算し琥珀バナーで表示、差額の原因メモを残せるフィールドを追加。
- 保存で残高調整の記録(既存モデルに準ずる。無ければ `Transaction` に差額調整として記録する等、既存の会計ロジック `src/lib/calculations.ts` に沿う)。

### 画面5: 経費 手入力
- 金額をテンキーで入力(大きい表示)。
- 科目(既存カテゴリ `src/lib/categories.ts` の一覧から選択)/支払方法/メモを選択・入力。
- 保存で `Transaction`(支出)として記録。

## 共通実装ルール
- 画面2・3は**編集可能な明細リスト＋合計照合バッジ**が必須。この2点が欠けている実装は不完全とみなす。
- 色はプロジェクトのamberトークンに対応させる(背景/本文/ミュート/オレンジ/緑/琥珀)。hex直書きは既存スタイルとの整合性を確認の上、Tailwindのトークン経由にする。
- 全データ操作は `storeId` スコープを維持し、既存の `auth.ts` の認可パターンに従う。
- モバイル幅 max 440px、タップ領域は44px以上を確保。

## 完了条件
- 5画面がモックアップの構成・配色に沿って表示される。
- 画面2・3で、明細編集→合計・照合結果が即座に再計算されることを確認できる。
- 既存の会計計算・データモデルとの整合性が取れている(型・lintエラーなし)。
