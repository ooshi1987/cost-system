## 2. 集計ロジック: `src/lib/dailyLedger.ts`（新規）
関数例: `getDailyLedger(storeId: string, year: number, month: number)`。

1. **売上サイド**: 対象月・店舗の `type='sale'` の取引を日付でグルーピングし、`method` ごとに金額を合算（例: 現金・クレジット・オンライン）。列の粒度は既存 `method` の値に合わせる（プロトタイプの「現金/クレジット/オンライン」は一例。実際の enum/選択肢に合わせて列を決める）。日ごとの売上合計も算出。
2. **支出サイド（仕入先別）**: 対象月・店舗の `type='expense'` の取引を日付×取引先（`vendor`、無ければ `category` 名で代用）でグルーピング。
   - **列は固定リストにしない**。当月の支出金額が多い取引先/科目 **上位5〜6件を動的に選び、それ以外を「その他」列に集約**する（Excelの列見出しは取引先名だが、本番では取引先が数十社に及ぶため、動的な上位N＋その他で再現する。列の並びは合計額の降順）。
   - 日ごとの支出合計も算出。
3. **差引**: `売上合計 − 支出合計`（日ごと）。
4. **月合計行**: 全列を月内で合算（各支払方法の合計・各取引先/その他の合計・売上合計・支出合計・差引合計）。
5. 戻り値の型例:
```ts
type DailyLedgerRow = {
  date: string;        // "2026-01-15"
  day: number;
  weekday: string;      // "水"
  salesByMethod: Record<string, number>;
  salesTotal: number;
  expenseByVendor: Record<string, number>; // 動的キー（上位N社名）＋ "その他"
  expenseTotal: number;
  net: number;          // salesTotal - expenseTotal
};
type DailyLedger = {
  vendorColumns: string[]; // 上位N社名（当月分、降順）＋ "その他"
  methodColumns: string[]; // 実際に使われている入金チャネル
  rows: DailyLedgerRow[];
  monthTotal: DailyLedgerRow; // date/day/weekdayは不要、他は同型
};
```

## 3. 表示コンポーネント: `DailyLedgerClient.tsx`
- プロトタイプの表構成（グループヘッダー「売上」緑／「仕入先別支出」amber、列ヘッダー、日別行、月合計行sticky）を、既存Tailwindのamber系トークンで再現。
- 列数は `methodColumns` / `vendorColumns` の実データに応じて可変（`grid-template-columns` を動的生成、または `<table>` + Tailwindでも可。横スクロールコンテナで包む）。
- 差引がプラス→ `text-green-600` 系、マイナス→ `text-red-600` 系。
- 月合計行は濃色背景で強調（sticky bottom）。
- **編集UIは一切追加しない**（表示専用）。行のホバー/クリックでの遷移も不要。

## 4. 出力（CSV / PDF）
- 既存にCSV/PDF出力の仕組みがあればそれに合わせて「日次集計表」用のエクスポートを追加。無ければまずCSV出力（表示中の月・店舗のテーブルをそのままCSV化）をスコープとし、PDF出力は既存の「税理士向けPDF出力」機能があれば同じ導線に載せる形で拡張する（無ければ別タスクとして切り出しを提案し、今回は実装しない）。

## 5. 横断事項
- **テナント/店舗分離**: 追加するクエリは必ず `storeId` スコープ＋既存の認可方式（`src/lib/auth.ts`）に従う。
- **スタイル**: 既存Tailwind（amber系）に合わせる。プロトタイプのhexを直書きしない。
- **パフォーマンス**: 月次集計はDB側で `groupBy`（Prisma の `groupBy`）を使い、日数×取引先のN+1を避ける。
- **既存機能への影響**: ダッシュボード・取引履歴など既存画面は無変更で動作すること（非破壊）。

## 受入条件
1. サイドバーに「日次集計表」が追加され、遷移できる。
2. 月選択で当該月の日別行（売上=現金/クレジット/オンライン等の内訳＋合計、支出=上位取引先＋その他の内訳＋合計、差引）が表示される。
3. 月合計行が全列について正しく集計され、テーブル最下部に固定表示される。
4. この画面から金額を編集する手段が存在しない（表示専用）。
5. 既存の画面・API・ナビは無変更で動作する。
6. `tsc --noEmit` / `eslint` をクリーンに保つ。
